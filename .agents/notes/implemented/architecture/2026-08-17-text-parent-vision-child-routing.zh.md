# Agent Note: 纯文本父模型路由与隔离视觉子模型

Status: implemented

[English](2026-08-17-text-parent-vision-child-routing.md) | 中文

## 问题

部署可能有意让主 DeepSeek agent 使用纯文本路由，同时仍需查看截图、图表和上传图片。把原始图片发送给该路由会产生无效请求；把视觉网关改成父模型会改变部署的推理与成本策略；让功能插件持有 API key 则会重复 Harness 的设置与凭据系统。浏览器此前还会直接把草稿图片作为 prompt 部分提交，因此只有宿主工具无法保证父模型请求始终只有文本。

## 决定

该功能由一个组合包编排三个插件。`@deepseek-ai/dsh-tool-vision-luna` 负责宿主侧资产授权、下载策略、委派、缓存、任务和 `gpt_luna_vision` 工具。`@deepseek-ai/dsh-client-ui-vision-luna` 负责浏览器图片接入，在上传成功后用不透明文本引用替换原始草稿图片 prompt 部分。`@deepseek-ai/dsh-vision-luna` 只以保守的策略默认值插入两个插件。现有 `ui-conversation` 服务提供单提供方图片接入适配器；没有提供方时保留此前发送原始图片的行为，重复提供方则明确失败，避免优先级取决于加载顺序。

视觉插件配置只命名 LLM 路由（`provider`、`model`）和非敏感执行策略。提供方 profile 仍位于 Harness 的 `llm-pi-ai` 设置命名空间，包括 `api`、`baseURL`、模型目录、图片模态、凭据引用、请求头、重试和传输设置。被引用的真实密钥仍位于“模型”页面、凭据提供方的仅所有者可读文档或启动环境。未知插件字段会被 schema 校验拒绝，因此 `apiKey`、`apiKeyEnv`、`baseURL` 及相关传输字段无法意外迁入插件。凭据仍由选中的 Harness 适配器逐请求解析；引用无法解析时，调用方收到 `LlmError('MISSING_CREDENTIAL')`，插件不会读取或改写它。

每次视觉调用都使用已注册的 `spawn` subagent 提供方和配置的视觉路由，深度为一；除了生成的结构化输出工具外，不向子模型提供其他工具；敌意图片 persona 要求把图片内容视为数据而非指令。子模型返回固定的证据 schema。只有经过校验的文本结果进入父模型工具 transcript；包含图片附件的子模型请求保留在子 Session 中。委派前解析提供方／模型能力，声明输入模态不含图片的路由会被拒绝。

图片在模型调用前进入持久化、按内容寻址的资产存储。`vision/asset` Session 事件把每个不透明的 `vision:<attachment-id>` 引用绑定到所属 Session；工具调用只能使用该 Session 权威事件中存在的引用。本地路径经文件系统能力解析，通过 realpath 和符号链接检查后仍须位于 Session workspace 内，且必须是字节数不超过限制、魔数受支持的普通文件。远程图片只接受 HTTPS、精确许可的 origin、无凭据且不是 IP 字面量的 URL、全部为公网地址的 DNS 结果、逐请求 DNS 固定、每次跳转重新校验、流式字节限制和受支持的图片魔数。每个批次都会在首次保存前完成全量校验和重复内容检查；不可变对象先于授权事件保存，只有 Session flush 成功后才返回回执。存储中途失败可能留下未被引用的内容寻址对象；flush 失败则保留待持久化事件，重试时会再次强制 flush，而不会把仅在内存中的事件视为已经持久化。

服务使用按父 Session 隔离的有界进程内 LRU 保存已完成的结构化结果，并在同一 Session 内合并相同的进行中请求。只要仍有其他订阅者等待，一个订阅者取消就不会终止共享任务。可选后台执行复用现有 jobs 能力。释放时停止接收新任务，中止活跃下载和子模型运行，等待它们结束，并通过 Cordis effect 注销所有贡献。

## 包拓扑

宿主与浏览器插件独立演进：前者保护模型侧输入，后者适配 GUI 提交路径。组合包有意保持浅层，不声明提供方端点或凭据引用，因此可跨部署复用。非 GUI 组合可以只挂载宿主插件，并通过附件 RPC 或其他可信客户端创建已授权资产引用。

## 验证

无密钥 ACP 快照使用一个确定性的双路由适配器，组装真实的附件存储、Session 持久化、subagent 驱动、工具注册表和视觉插件。fixture 会拒绝父模型请求中的任何图片块，要求子模型请求使用 `zaizaizhao/gpt-5.6-luna` 且包含图片块，并通过结构化输出返回证据。提交的父、子 Session 产物固定了彼此独立的请求 header 与 transcript。包测试覆盖配置拒绝、凭据错误保留、路由模态、缓存竞态、生命周期排空、Session 授权、路径约束、URL 校验、重定向、DNS 固定、字节限制、图片签名、原子上传、浏览器回退、适配器替换以及失败后保留草稿。

## 考虑过的替代方案

**把图片发给父模型，并依赖提供方忽略。**纯文本路由会在模型决定如何处理之前拒绝请求；虚报图片支持还会让持久化 Session 重复一个永远无法成功的请求。

**在功能插件中配置视觉端点和 API key。**这会产生第二套提供方目录与凭据存储，使“模型”页面和热更新无法拥有该路由，并增加可能暴露密钥的组件数量。

**让视觉模型成为主 agent。**这会为只在少量图片上需要的能力改变每一轮请求的路由、推理行为、延迟和成本。

**把所有代码放进一个包。**只有宿主的 ACP 或 headless 部署会被迫携带浏览器代码，GUI 关注点也会与安全敏感的输入和模型执行共享生命周期。

**允许工具参数直接使用无限制文件路径或任意 URL。**模型生成的参数不构成逃离 Session workspace 或联系任意主机的权限。当前实现的路径入口始终受 Agent 文件系统能力限制，URL 入口要求运维者提供精确白名单，浏览器输入则使用 Session 范围的不透明引用，从而保持回放可重建。

## 影响

主模型请求保持纯文本，现有 Harness 配置仍是模型路由和凭据的唯一来源。部署无需重新构建插件即可更换视觉提供方，所有模型可见结果都可从 Session log 重建。代价是多一次子模型请求、持久资产存储、浏览器到宿主的上传步骤，以及显式配置支持视觉的路由。进程内结果缓存不会跨重启保留，后台任务不会让子模型运行跨进程故障持久化，远程 URL 接入有意拒绝私网和非 HTTPS 来源，组合包同一时间只支持一个浏览器图片接入提供方。
